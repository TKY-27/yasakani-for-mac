Part 1: Operational Boundaries
The system serves only one active request at a time, and all model state is exclusively owned by a single execution context. This constraint is not a temporary defect; it is a deliberate product choice for single-GPU local inference. It lets the memory planner determine workspace, cache, and graph execution addresses in advance, and it makes the state transitions for cancellation, failure, and recovery easier to verify.

Part 2: Prefill
The input is first rendered through a template and tokenized, then fed into the model in fixed-size blocks. Each block reads the state that has already been committed and atomically advances the frontier. Timing must distinguish host-side preparation, vision preprocessing, text prefill, and the first output token; file reads and model loading must not be mixed into throughput.

Part 3: Decoding
Standard decoding commits one token per round, while speculative decoding can verify multiple candidates and commit a contiguous prefix. Regardless of how many candidates are accepted, the published output, KV cache, loop state, and counters must all correspond to the same committed position; partially updated state must not be left behind.

Part 4: Long Context
As the context grows, fixed weight reads and the continually growing attention-cache reads jointly determine latency. Reports should provide absolute speed, relative retention, and the actual prompt token count, and should record the cache format, maximum capacity, sampler, and graph execution state.

Part 5: Reproducibility
Stable inputs must be preserved as the message files actually sent, with their source and token count recorded. Formal runs must not download web pages ad hoc, select questions at random, or delete slower samples. Every reported number must be traceable to a specific model, command, input, and service log.

Part 6: Interpreting Results
A single isolated fastest run cannot prove stable performance, and a single text with a high acceptance rate cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be presented separately rather than merged into a meaningless aggregate average.
