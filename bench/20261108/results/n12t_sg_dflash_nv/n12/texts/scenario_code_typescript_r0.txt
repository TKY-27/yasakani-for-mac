stats.ts: RunningStats class or a plain object with functions.

Mean = sum/count. Sample standard deviation: use the online formula to avoid holding all values: var = (sumSq - (sum*sum)/count) / (count-1). There's numerical cancellation risk; more stable is Welford's algorithm: hold M2 (sum of squared differences). Welford:
```
delta = x - mean; mean += delta / n; delta2 = x - mean; M2 += delta * delta2;
variance = M2 / (n - 1)
```
That's the standard approach; use Welford for numerical stability. Document it.

Median: bounded reservoir sampling. When adding value x to a group with current n (n is the group's count including x): standard reservoir: when n <= capacity, add to reservoir (keep it nearly sorted? keep as array and sort at snapshot time). When n > capacity, with probability capacity/n, replace a random index. To avoid the dependency on Math.random in tests... well, it's fine; in tests, seed via a dependency-injected rng function, defaulting to Math.random. Good design: `createReservoir(capacity, rng)`.

Actually, a simpler and more deterministic approach: a fixed-capacity circular buffer (ring) storing the last K values; the median is computed from those K — approximating the median of the recent window. This is deterministic and simpler, but biased toward the most recent values. Reservoir sampling gives a uniform random sample of all values → better approximation of the overall median. Use reservoir sampling with injectable RNG, defaulting to Math.random. Keep capacity at, e.g., 512 per group.

Also track count so we know when the median is approximate (count > reservoir.length? After sampling, the reservoir stays at capacity; approximation flag = count > capacity).
