# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但不得翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用已禁用、缓存命中计数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍视为有效观测；因客户端断开连接而丢失的响应则不视为有效。报告区分服务器内部 TTFT 与网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

## 双语术语表

| 术语 (Term) | 中文 (Chinese) | 简要说明 (Note) |
|---|---|---|
| Release procedure | 发布流程 | 软件或模型版本发布的标准化步骤。 |
| Release owner | 发布负责人 | 负责确保发布过程合规且数据准确的人员。 |
| Identifier | 标识符 | 用于唯一识别数据或资源的字符串，如 ID。 |
| Request ID | 请求 ID | 用于追踪特定 API 请求的唯一标识符。 |
| Max context | 最大上下文 | 模型处理输入和输出时允许的最大 token 数量。 |
| KV dtype | KV 数据类型 | 键值缓存（Key-Value Cache）中存储数据的数据类型。 |
| MTP rounds | MTP 轮次 | 多 token 预测（Multi-Token Prediction）的迭代次数。 |
| Fixture hash | 测试夹具哈希 | 用于验证测试数据完整性的哈希值。 |
| Prompt-token count | 提示词 token 数 | 输入提示词中包含的 token 总数。 |
| Generation | 生成 | 模型根据输入生成文本的过程。 |
| Warmup | 预热 | 正式测量前运行以稳定系统状态的阶段。 |
| Unmeasured request | 未测量请求 | 不计入性能统计的测试请求。 |
| Sequential responses | 顺序响应 | 按顺序依次返回的多个响应结果。 |
| Invalidate | 使无效 | 标记数据或结果不再有效。 |
| Headline | 头条/主要指标 | 报告中展示的核心性能指标。 |
| Prefix reuse | 前缀复用 | 利用相同前缀的缓存以加速推理的技术。 |
| Cache-hit count | 缓存命中计数 | 成功从缓存中读取数据的次数。 |
| GPU process | GPU 进程 | 占用图形处理器资源的运行进程。 |
| TTFT | 首 token 延迟 | Time To First Token，从请求发出到收到第一个 token 的时间。 |
| Prefill | 预填充 | 模型处理输入提示词并建立初始上下文的阶段。 |
