# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但不要翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀重用已禁用，缓存命中计数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍被视为有效观察；因客户端断开连接而丢失的响应则不然。报告区分了服务器内部 TTFT 和网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

## 双语术语表 (Bilingual Glossary)

1. **Release procedure** / 发布流程：指软件版本从准备到最终发布的标准化步骤。
2. **Request ID** / 请求标识符：用于唯一识别特定 API 调用或事务的字符串。
3. **Max Context** / 最大上下文长度：模型能够处理的最大输入加输出的 token 数量限制。
4. **KV Dtype** / KV 数据类型：键值（Key-Value）缓存中存储数据的数据类型（如 float16, bfloat16）。
5. **MTP Rounds** / MTP 轮次：多 Token 预测（Multi-Token Prediction）过程中执行的迭代次数。
6. **Fixture Hash** / 测试夹具哈希值：用于验证测试数据完整性和一致性的哈希摘要。
7. **Prompt Token Count** / 提示词 Token 数：输入提示词中包含的 token 总数。
8. **Warmup** / 预热：在正式测量前运行以稳定系统性能的非计时请求。
9. **Unmeasured Request** / 未测量请求：不计入性能统计数据的请求。
10. **Sequential Responses** / 顺序响应：按时间顺序依次返回的多个响应结果。
11. **Invalidate Block** / 使块失效：标记整个数据块或测试批次为无效，需重新执行。
12. **Withhold Headline** / 暂缓发布标题：在确认数据无误前不公开主要结论或指标。
13. **Prefix Reuse** / 前缀重用：利用之前计算过的相同前缀部分的 KV 缓存以加速推理。
14. **Cache-Hit Count** / 缓存命中计数：成功从缓存中读取而非重新计算的次数。
15. **GPU Process** / GPU 进程：占用图形处理器资源的操作系统进程。
16. **Valid Observation** / 有效观察：符合实验条件、可用于数据分析的结果。
17. **Client Disconnected** / 客户端断开：用户端主动或意外终止连接导致的数据丢失。
18. **TTFT** / 首字延迟 (Time To First Token)：从发送请求到收到第一个生成 token 的时间。
19. **Network-Observed Time** / 网络观测时间：包含网络传输延迟在内的端到端感知时间。
20. **Prefill** / 预填充：模型处理输入提示词并构建初始 KV 缓存的阶段。
