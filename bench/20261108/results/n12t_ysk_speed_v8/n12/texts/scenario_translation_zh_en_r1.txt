The system serves only one active request, and all model state is exclusively owned by a single execution context. This constraint is not a temporary defect; it is an explicit product choice for single-GPU local inference. Part 2: Prefill
Input is first template-rendered and tokenized, then enters the model in fixed-size blocks. Each block reads state that has already been committed and atomically advances the frontier. Timing must separate host preparation, visual preprocessing, text prefill, and the first output token; file reads and model loading must not be mixed into throughput.

Part 3: Decoding
Ordinary decoding commits one token per step. Speculative decoding can validate multiple candidates and commit one contiguous accepted prefix. Regardless of how many candidates are accepted, the public output, KV cache, loop state, and counters must all correspond to the same committed position; a state that is only half-updated must not be left behind.

Part 4: Long Context
As context grows, reads of fixed model weights and reads of the growing attention cache jointly determine latency. The report should give absolute speed, relative retention rate, and actual prompt token count, and should record cache format, maximum capacity, sampler, and graph execution status.

Part 6: Result Interpretation
