# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但不要翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需确认前缀复用已禁用，缓存命中计数为零，且没有无关的 GPU 进程正在运行。自然停止的响应仍视为有效观测；因客户端断开连接而丢失的响应则不然。报告需区分服务器内部 TTFT 与网络观测时间，并说明首个生成的 token 被分配给 prefill 阶段。

## 双语术语表

1. **Release procedure** (发布流程): 指软件或模型版本从准备到发布的标准化步骤。
2. **Release owner** (发布负责人): 负责监督并确保发布过程合规的人员。
3. **Identifier** (标识符): 用于唯一标识数据或请求的字符串，如 `request_id`。
4. **Fixture** (测试夹具): 用于测试的固定数据集或环境配置。
5. **Hash** (哈希值): 数据的摘要值，用于验证完整性。
6. **Prompt-token count** (提示词 token 数量): 输入提示中包含的 token 总数。
7. **Warmup** (预热): 正式测量前进行的非计时请求，以稳定系统状态。
8. **Unmeasured request** (未测量请求): 不纳入性能统计的请求。
9. **Sequential responses** (顺序响应): 按顺序生成的多个响应结果。
10. **Invalidate** (使无效): 标记数据或结果不可用。
11. **Withhold** (保留/暂缓发布): 暂时不公开特定信息。
12. **Prefix reuse** (前缀复用): 利用相同前缀缓存以加速推理的技术。
13. **Cache-hit count** (缓存命中计数): 成功从缓存中读取数据的次数。
14. **GPU process** (GPU 进程): 占用图形处理器资源的运行程序。
15. **Observation** (观测): 在实验或测试中记录到的数据点。
16. **TTFT** (Time To First Token): 从请求发出到收到第一个 token 的时间。
17. **Prefill** (预填充): 模型处理输入提示并生成初始上下文的阶段。
18. **Max completion tokens** (最大完成 token 数): 模型允许生成的最大 token 数量。
19. **Seed** (随机种子): 用于确保随机过程可复现的固定数值。
20. **Stream** (流式传输): 是否以流式方式逐步返回生成内容的布尔标志。
