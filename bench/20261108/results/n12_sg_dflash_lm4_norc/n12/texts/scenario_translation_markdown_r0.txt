# 发布流程

发布负责人必须原样保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但不要翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

## 备注

操作员需检查前缀复用已禁用，缓存命中数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍视为有效观测；因客户端断开连接而丢失的响应则不然。报告区分了服务器内部 TTFT 与网络观测时间，并说明首个生成的 token 被分配给 prefill 阶段。

## 双语术语表

1.  **Release procedure** (发布流程): 软件或模型版本从准备到发布的标准化步骤。
2.  **Release owner** (发布负责人): 负责确保发布过程合规及数据完整性的主要责任人。
3.  **Identifier** (标识符): 用于唯一识别请求、配置或数据块的字符串或变量名。
4.  **`request_id`** (请求 ID): 用于追踪特定 API 请求生命周期的唯一标识符。
5.  **`max_context`** (最大上下文): 模型处理输入和输出时允许的最大 token 数量限制。
6.  **`kv_dtype`** (KV 数据类型): 键值缓存（Key-Value Cache）中存储数据的数据类型（如 float16, int8）。
7.  **`mtp_rounds`** (MTP 轮数): 多 token 预测（Multi-Token Prediction）过程中执行的迭代轮数。
8.  **Fixture** (测试夹具): 用于测试或基准测试的预定义数据集合或环境配置。
9.  **Hash** (哈希值): 用于验证数据完整性的固定长度字符串摘要。
10. **Prompt-token count** (提示词 token 数): 输入提示词中包含的 token 总数。
11. **Warmup** (预热): 在正式测量前运行非计时请求以稳定系统状态的过程。
12. **Unmeasured request** (非测量请求): 不用于性能统计，仅用于系统初始化的请求。
13. **Sequential responses** (顺序响应): 按时间顺序依次生成并记录的多个响应结果。
14. **Invalidate** (使无效): 标记数据块或结果不可用，通常因测试失败或数据损坏。
15. **Headline** (头条数据): 报告中展示的关键性能指标或主要结论。
16. **Prefix reuse** (前缀复用): 利用之前请求中已计算的 KV 缓存来加速相似前缀的新请求。
17. **Cache-hit count** (缓存命中数): 成功从缓存中检索到所需数据的次数。
18. **GPU process** (GPU 进程): 占用图形处理单元资源的操作系统进程。
19. **TTFT** (首字延迟): Time To First Token，从请求发出到收到第一个生成 token 的时间。
20. **Prefill** (预填充): 模型处理输入提示词并生成初始 KV 缓存的阶段。
21. **Network-observed time** (网络观测时间): 客户端通过网络测量到的端到端延迟。
22. **Observation** (观测值): 在基准测试或监控过程中记录的一个具体数据点。
