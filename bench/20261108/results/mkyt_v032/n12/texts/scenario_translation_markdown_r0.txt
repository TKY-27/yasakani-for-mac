# 发布流程

发布负责人必须原样保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但请勿翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需确认前缀复用已禁用、缓存命中计数为零，且没有无关的 GPU 进程正在运行。自然停止的响应仍视为有效观测；因客户端断开连接而丢失的响应则不然。报告区分了服务器内部 TTFT 与网络观测时间，并说明首个生成的 token 被分配给 prefill 阶段。

## 双语术语表

| 英文术语 | 中文术语 | 简要说明 |
| :--- | :--- | :--- |
| Release procedure | 发布流程 | 软件或模型版本发布的标准化步骤。 |
| Release owner | 发布负责人 | 负责协调和执行发布流程的人员。 |
| Identifier | 标识符 | 用于唯一识别对象或数据的字符串，如 ID。 |
| Fixture | 测试夹具 | 测试中使用的固定数据或环境配置。 |
| Prompt-token count | 提示词 Token 数量 | 输入提示词中包含的 Token 总数。 |
| Warmup | 预热 | 正式测试前使系统达到稳定状态的阶段。 |
| Unmeasured request | 未测量请求 | 不计入性能统计的初始请求。 |
| Sequential responses | 顺序响应 | 按顺序依次返回的多个响应结果。 |
| Invalidate | 使无效 | 标记数据或结果不再有效。 |
| Headline | 头条/主要结论 | 报告中最重要的核心指标或结论。 |
| Prefix reuse | 前缀复用 | 利用相同前缀缓存以加速推理的技术。 |
| Cache-hit count | 缓存命中计数 | 成功从缓存中读取数据的次数。 |
| GPU process | GPU 进程 | 占用图形处理器资源的运行进程。 |
| Observation | 观测 | 在实验或测试中记录到的数据点。 |
| Client disconnected | 客户端断开 | 客户端主动或被动终止连接。 |
| Server-internal TTFT | 服务器内部首字延迟 | 服务器内部记录的首个 Token 生成时间。 |
| Network-observed time | 网络观测时间 | 通过网络层观测到的响应时间。 |
| First generated token | 首个生成 Token | 模型生成的第一个输出 Token。 |
| Prefill | 预填充 | 处理输入提示词并构建初始上下文的阶段。 |
| Model | 模型 | 用于执行推理任务的 AI 模型实例。 |
| Max completion tokens | 最大完成 Token 数 | 允许生成的最大 Token 数量限制。 |
| Seed | 随机种子 | 用于控制随机数生成器初始状态的数值。 |
| Stream | 流式传输 | 以流的方式逐步返回生成结果。 |
