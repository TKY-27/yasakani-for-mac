**Part 1: Operational Boundaries**
The system services only one active request at a time, with all model state exclusively owned by a single execution thread. This constraint is not a temporary defect but a deliberate product choice for single-GPU local inference. It allows the memory planner to pre-determine workspace, cache, and graph execution addresses, and makes state transitions for cancellation, failure, and recovery easier to verify.

**Part 2: Prefill**
Input is first processed through template rendering and tokenization, then fed into the model in fixed-size blocks. Each block reads the previously committed state and atomically advances the frontier. Timing must distinguish between host preparation, visual preprocessing, text prefill, and the first output token; file reading or model loading must not be mixed into throughput metrics.

**Part 3: Decoding**
Standard decoding commits one token per round, while speculative decoding can verify multiple candidates and commit a contiguous prefix. Regardless of how many candidates are accepted, the public output, KV cache, loop state, and counters must all correspond to the same committed position; no partially updated state may be left behind.

**Part 4: Long Context**
As context grows, latency is jointly determined by fixed weight reads and the ever-growing attention cache reads. Reports should provide absolute speed, relative retention rate, and actual prompt token count, and must record cache format, maximum capacity, sampler, and graph execution status.

**Part 5: Reproducibility**
Stable inputs must be saved as the actual message files sent, with source and token count recorded. Formal runs must not involve ad-hoc web downloads, random question selection, or deletion of slower samples. Every number must be traceable back to a specific model, command, input, and service log.

**Part 6: Interpretation of Results**
A single isolated fastest run cannot prove stable performance, and a single high-acceptance-rate text cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be presented separately, rather than mixed into a meaningless overall average.
