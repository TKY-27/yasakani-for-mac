# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但不得翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用是否已禁用、缓存命中计数是否为零，以及是否有无关的 GPU 进程正在运行。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则不是。报告区分了服务器内部 TTFT 与网络观测时间，并说明首个生成的 token 被分配给 prefill 阶段。

## 双语术语表 (Bilingual Glossary)

1. **Release procedure / 发布流程**: The standardized sequence of steps to deploy a new model version.
2. **Release owner / 发布负责人**: The individual accountable for the integrity and success of the release process.
3. **Identifier / 标识符**: A unique string used to track specific data points or configurations.
4. **Request ID / 请求 ID**: A unique identifier assigned to each API request for tracing.
5. **Max context / 最大上下文**: The maximum number of tokens the model can process in a single window.
6. **KV dtype / KV 数据类型**: The data type used for storing Key-Value cache entries.
7. **MTP rounds / MTP 轮次**: The number of Multi-Token Prediction iterations performed.
8. **Phase / 阶段**: A distinct stage in the release workflow (e.g., prepare, measure).
9. **Required evidence / 必需证据**: The specific data points needed to validate a phase's success.
10. **Failure action / 失败操作**: The predefined response when a phase does not meet criteria.
11. **Fixture hash / 测试夹具哈希**: A checksum of the test data to ensure consistency.
12. **Prompt-token count / 提示词 Token 数**: The number of tokens in the input prompt.
13. **Warmup / 预热**: The initial phase to stabilize system performance before measurement.
14. **Unmeasured request / 未测量请求**: A request sent during warmup that is not included in final metrics.
15. **Measure / 测量**: The phase where performance metrics are collected.
16. **Sequential responses / 顺序响应**: Responses generated one after another in a defined order.
17. **Invalidate / 使无效**: To discard data due to detected anomalies or errors.
18. **Publish / 发布**: The final phase where results are made available.
19. **Headline / 标题/主要指标**: The primary performance metric highlighted in the report.
20. **Prefix reuse / 前缀复用**: The mechanism of reusing previously computed KV cache for common prefixes.
21. **Cache-hit count / 缓存命中计数**: The number of times the KV cache was successfully utilized.
22. **GPU process / GPU 进程**: A computational task running on the Graphics Processing Unit.
23. **TTFT / 首字延迟 (Time To First Token): The time taken from request initiation to the first token generation.
24. **Prefill / 预填充**: The initial processing stage where the input prompt is encoded.
