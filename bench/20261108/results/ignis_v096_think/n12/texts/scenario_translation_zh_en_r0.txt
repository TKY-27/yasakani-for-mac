### Part 1: Runtime Boundary

The system serves only one active request, and all model state is exclusively owned by a single execution process. This restriction is not a temporary defect; it is a deliberate design choice by the product for single-GPU local inference. It allows the memory planner to determine workspace, cache, and graph execution addresses in advance, and it also makes the state transitions for cancellation, failure, and recovery easier to verify.

### Part 2: Prefill

The input first goes through template rendering and tokenization, and then enters the model in fixed-size chunks. Each chunk reads previously committed state and atomically advances the frontier. Timing measurements must distinguish host preparation, visual preprocessing, text prefill, and the first output token; file reads or model loading must not be mixed into throughput figures.

### Part 3: Decoding

Ordinary decoding commits one token per round. Speculative decoding can verify multiple candidates and commit a contiguous prefix. Regardless of how many candidates are accepted, the user-visible output, KV cache, recurrent state, and counters must all correspond to the same committed position; no state may be left only half-updated.

### Part 4: Long Context

As context grows, fixed-weight reads and the continually growing attention-cache reads jointly determine latency. Reports should provide absolute speed, relative retention rate, and the actual number of prompt tokens, and should record the cache format, maximum capacity, sampler, and graph execution state.

### Part 5: Reproducibility

Stable inputs must be saved as the actual message files sent, together with their source and token counts. Formal runs must not download web pages on the fly, randomly select questions/prompts, or remove slower samples. Every reported number must be traceable back to an explicit model, command, input, and service log.

### Part 6: Interpretation of Results

A single isolated fastest run cannot prove stable performance, and a single text with a high acceptance rate cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be reported separately, rather than being blended into an aggregate average that lacks meaningful interpretation.
