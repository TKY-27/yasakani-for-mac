## 备注

## 双语术语表 / Bilingual Glossary

| Term | 中文 | 说明 |
|---|---|---|
| `request_id` | 请求标识 | 唯一标识一次请求，便于追踪证据和失败原因。 |
| `max_context` | 最大上下文 | 限制模型请求可使用的上下文长度或规模。 |
| `kv_dtype` | KV 数据类型 | 指定 key-value 缓存使用的数值数据类型。 |
| `mtp_rounds` | MTP 轮数 | 指定多 token 预测或 MTP 执行的轮数。 |
| release owner | 发布负责人 | 负责按规程执行发布并保留关键证据的角色。 |
| Phase | 阶段 | 发布流程中需要满足证据和失败处理规则的步骤。 |
| prepare | 准备 | 在生成前完成夹具和提示词元数核验的阶段。 |
| warmup | 预热 | 执行一次未测量请求以完成服务预热。 |
| measure | 测量 | 采集连续响应并用于性能观测的阶段。 |
| publish | 发布 | 输出摘要和每请求数据并对外给出结果的阶段。 |
| fixture hash | 夹具哈希 | 用于确认测试夹具内容未发生变化的校验值。 |
| prompt-token count | 提示词元数 | 输入提示中 token 的数量。 |
| generation | 生成 | 模型产生响应的过程。 |
| unmeasured request | 未测量请求 | 不纳入测量统计的一次请求。 |
| sequential responses | 连续响应 | 按顺序连续返回的多个响应。 |
| complete block | 完整块 | 测量中视为一个整体、需整体作废的数据块。 |
| summary | 摘要 | 汇总整体结果的报告部分。 |
| per-request rows | 每请求行 | 按单个请求拆分的明细行。 |
| headline | 主要结果 | 报告中最突出、需要审慎发布的总括结论。 |
| prefix reuse | 前缀复用 | 复用已有前缀计算或缓存以加速请求的机制。 |
| cache-hit count | 缓存命中次数 | 请求命中缓存的次数。 |
| GPU process | GPU 进程 | 占用或运行在 GPU 上的进程。 |
| response | 响应 | 服务端返回给客户端的一次结果。 |
| client disconnected | 客户端断开 | 客户端提前断开连接导致响应无法完成或观测。 |
| TTFT | 首 token 时延 | 从请求开始到首个 token 返回所经历的时延。 |
| network-observed time | 网络观测时间 | 在网络或客户端侧观测到的时间。 |
