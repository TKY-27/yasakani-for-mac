# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但不得翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用已禁用、缓存命中计数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍视为有效观测；因客户端断开连接而丢失的响应则不视为有效。报告区分了服务器内部 TTFT 与网络观测时间，并说明首个生成的 token 被分配给 prefill 阶段。

## 双语术语表

| English Term | 中文术语 | Note |
|---|---|---|
| release owner | 发布负责人 | 负责确保发布流程合规的人员 |
| request_id | 请求标识符 | 用于唯一标识单个 API 请求的字符串 |
| max_context | 最大上下文长度 | 模型可处理的最大输入 token 数 |
| kv_dtype | KV 数据类型 | 键值缓存存储的数据类型（如 float16） |
| mtp_rounds | MTP 轮次 | 多 token 预测的迭代次数 |
| fixture hash | 测试数据哈希 | 用于验证测试数据完整性的哈希值 |
| prompt-token count | 提示词 token 数量 | 输入提示词中包含的 token 总数 |
| warmup | 预热 | 正式测量前的非计时请求阶段 |
| unmeasured request | 未计时请求 | 不纳入性能统计的请求 |
| sequential responses | 顺序响应 | 按顺序生成的多个响应 |
| invalidate | 使无效 | 标记数据或结果不可用 |
| withhold | 保留/扣留 | 暂时不发布或展示信息 |
| prefix reuse | 前缀复用 | 复用相同前缀以加速推理 |
| cache-hit count | 缓存命中计数 | 命中缓存的次数统计 |
| GPU process | GPU 进程 | 占用 GPU 资源的操作系统进程 |
| TTFT | 首 token 时间 | Time To First Token，首个 token 生成时间 |
| prefill | 预填充 | 处理输入提示词以生成初始 KV 缓存的阶段 |
| stream | 流式传输 | 是否以流式方式返回响应 |
| seed | 随机种子 | 用于确保生成结果可复现的固定值 |
| max_completion_tokens | 最大补全 token 数 | 模型生成的最大输出 token 数 |<|im_end|>
