**Part 1: Operational Boundaries**
The system services only one active request at a time, with all model states exclusively occupied by a single execution thread. This restriction is not a temporary defect, but a deliberate product choice made for single-GPU local inference. It allows the memory planner to pre-determine workspace, cache, and graph execution addresses, and also makes state transitions for cancellation, failure, and recovery easier to verify.

**Part 2: Prefill**
Input first undergoes template rendering and tokenization, then enters the model in fixed-size blocks. Each block reads previously committed state and atomically advances the frontier. Timing must distinguish between host preparation, visual preprocessing, text prefill, and the first output token; file reading or model loading must not be mixed into throughput metrics.

**Part 3: Decoding**
Standard decoding commits one token per iteration, while speculative decoding can verify multiple candidates and commit a contiguous prefix. Regardless of how many candidates are accepted, the public output, KV cache, loop state, and counters must all correspond to the same committed position; no partially updated state may be left behind.

**Part 4: Long Context**
As context grows, latency is jointly determined by fixed weight reads and the continuously growing attention cache reads. Reports should provide absolute speed, relative retention rate, and actual prompt token count, while documenting cache format, maximum capacity, sampler, and graph execution status.

**Part 5: Reproducibility**
Stable inputs must be saved as actual message files sent, with source and token count recorded. Formal runs must not involve temporary web downloads, random question selection, or deletion of slower samples. Every number must be traceable back to a specific model, command, input, and service log.

**Part 6: Result Interpretation**
A single isolated fastest run cannot prove stable performance, and a single high acceptance rate text cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be presented separately, rather than being mixed into a meaningless overall average.

**Chinese-English Glossary**

1.  **运行边界 (Operational Boundaries)**: The defined limits and constraints within which the system operates.
2.  **活动请求 (Active Request)**: The currently being processed user query or task.
3.  **模型状态 (Model State)**: The internal data structures (weights, caches, counters) holding the current progress of the model.
4.  **执行程序 (Execution Thread/Process)**: The specific software process or thread handling the inference.
5.  **独占 (Exclusive Occupation)**: Access restricted to a single entity, preventing concurrent access.
6.  **单卡本地推理 (Single-GPU Local Inference)**: Running AI models locally on a single graphics processing unit.
7.  **内存规划器 (Memory Planner)**: The component responsible for allocating and managing memory resources.
8.  **工作区 (Workspace)**: The temporary memory area used for intermediate calculations.
9.  **图执行地址 (Graph Execution Address)**: The memory location where the computation graph is executed.
10. **状态转换 (State Transition)**: The change from one defined state to another (e.g., running to failed).
11. **预填充 (Prefill)**: The initial phase of processing input tokens to generate the first output.
12. **模板渲染 (Template Rendering)**: The process of filling in a prompt template with specific variables.
13. **分词 (Tokenization)**: Breaking text into smaller units (tokens) for the model to process.
14. **原子地推进 (Atomically Advance)**: Moving the processing frontier forward in a single, indivisible step to ensure consistency.
15. **前沿 (Frontier)**: The current boundary of processed data in the sequence.
16. **主机准备 (Host Preparation)**: CPU-side tasks performed before GPU computation begins.
17. **视觉预处理 (Visual Preprocessing)**: Steps taken to prepare image data for the model (e.g., resizing, normalization).
18. **推测解码 (Speculative Decoding)**: A technique where a draft model proposes multiple tokens, which the main model verifies in parallel.
19. **连续前缀 (Contiguous Prefix)**: A sequence of tokens starting from the beginning that are all accepted.
20. **KV 缓存 (KV Cache)**: Key-Value cache storing attention keys and values to avoid recomputation.
21. **长上下文 (Long Context)**: Processing inputs with a large number of tokens.
22. **注意力缓存 (Attention Cache)**: The specific portion of the KV cache used for attention mechanisms.
23. **相对保留率 (Relative Retention Rate)**: A metric comparing performance under long context to baseline performance.
24. **可复现性 (Reproducibility)**: The ability to obtain the same results when repeating an experiment.
25. **采样器 (Sampler)**: The algorithm used to select the next token from the probability distribution.
26. **token 分布 (Token Distribution)**: The statistical pattern of how tokens appear in different types of content.<|im_end|>
