# 发布流程

发布负责人必须精确保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将散文部分翻译成中文，但请勿翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用（prefix reuse）是否已禁用、缓存命中计数（cache-hit count）是否为零，以及是否有无关的 GPU 进程正在运行。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则不被视为有效。报告区分了服务器内部的时间到首令牌（TTFT）与网络观测时间，并解释说第一个生成的令牌被分配给预填充（prefill）阶段。

## 双语术语表 (Bilingual Glossary)

1. **Release procedure** (发布流程): 指软件版本从准备到最终发布的标准化步骤。
2. **Release owner** (发布负责人): 负责协调和监督发布过程的人员。
3. **Identifier** (标识符): 用于唯一标识特定实体或参数的名称，如 `request_id`。
4. **Prose** (散文/正文): 指文档中非代码、非表格的自然语言描述部分。
5. **Fixture hash** (测试夹具哈希): 用于验证测试数据完整性的哈希值。
6. **Prompt-token count** (提示词令牌计数): 输入提示词中包含的令牌（token）数量。
7. **Warmup** (预热): 在服务正式测量前运行非测量请求以稳定系统的过程。
8. **Unmeasured request** (非测量请求): 用于预热但不计入性能统计的请求。
9. **Sequential responses** (顺序响应): 按顺序连续发送并接收的多个响应。
10. **Invalidate** (使无效/作废): 将数据或结果标记为不可用或错误。
11. **Withhold** (扣留/暂缓发布): 暂时不发布或公开某些信息。
12. **Prefix reuse** (前缀复用): 利用相同前缀的缓存以加速推理的技术。
13. **Cache-hit count** (缓存命中计数): 成功从缓存中检索数据的次数。
14. **GPU process** (GPU 进程): 在图形处理单元上运行的计算任务。
15. **Observation** (观测): 在实验或测试中记录到的数据点或事件。
16. **TTFT** (Time To First Token, 首令牌时间): 从请求发出到收到第一个生成令牌的时间。
17. **Prefill** (预填充): 大语言模型处理输入上下文以生成初始状态的过程。
18. **Max completion tokens** (最大完成令牌数): 模型单次响应允许生成的最大令牌数量。
19. **Seed** (种子): 用于控制随机数生成器以确保结果可复现的参数。
20. **Stream** (流式传输): 逐步返回生成内容而非等待完整响应的模式。
21. **KV dtype** (键值数据类型): 键值（Key-Value）缓存中数据的数据类型。
22. **MTP rounds** (多令牌预测轮数): 多令牌预测（Multi-Token Prediction）中涉及的迭代轮数。<|im_end|>
