# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但请勿翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

## 备注

操作员需检查前缀重用已禁用、缓存命中计数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍被视为有效观察；因客户端断开连接而丢失的响应则不是。报告区分了服务器内部的 TTFT 和网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

## 双语术语表

1. **Release procedure / 发布流程**: 软件版本从开发到生产环境上线的标准化步骤集合。
2. **Release owner / 发布负责人**: 负责确保发布流程合规、完整并按时交付的角色。
3. **Identifier / 标识符**: 用于唯一区分数据对象或系统配置的字符串，如 ID 或名称。
4. **Prose / 正文**: 文档中除代码和结构化数据外的自然语言描述部分。
5. **Fixture / 测试夹具**: 在测试或基准测试中使用的固定数据集或配置环境。
6. **Hash / 哈希值**: 数据块的唯一数字指纹，用于验证数据完整性。
7. **Prompt-token count / 提示词 Token 数量**: 输入提示词经过分词器处理后产生的 Token 总数。
8. **Warmup / 预热**: 系统启动后进行的非测量性请求，旨在加载模型权重和初始化缓存。
9. **Unmeasured request / 未测量请求**: 不计入性能统计指标，仅用于系统初始化的请求。
10. **Sequential responses / 顺序响应**: 按时间顺序依次生成并返回的多个响应结果。
11. **Invalidate / 使无效**: 标记数据块或测试结果不可用，通常因异常或污染导致。
12. **Headline / 头条指标**: 报告中展示的核心性能汇总数据，如平均延迟或吞吐量。
13. **Prefix reuse / 前缀重用**: 利用相同前缀的 KV 缓存加速推理的技术，此处指需禁用的状态。
14. **Cache-hit count / 缓存命中计数**: 请求中成功从缓存中读取而非重新计算的 Token 或块数量。
15. **GPU process / GPU 进程**: 占用图形处理单元资源的操作系统进程。
16. **Observation / 观察**: 在实验或测试过程中记录的有效数据点。
17. **TTFT / 首 Token 延迟**: Time To First Token，从发送请求到收到第一个生成 Token 的时间。
18. **Prefill / 预填充**: 模型处理输入提示词并生成初始 KV 缓存的阶段。
19. **Stream / 流式传输**: 将生成内容分块实时发送给用户，而非等待完整响应。
20. **Seed / 随机种子**: 用于控制随机数生成器，确保实验可复现的整数参数。<|im_end|>
