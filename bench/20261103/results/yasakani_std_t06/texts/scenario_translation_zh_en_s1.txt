**Part 1: Operational Boundaries.** The system services only one active request at a time, with all model state exclusively owned by a single execution thread. This constraint is not a temporary flaw but a deliberate product decision tailored for single-GPU local inference. It enables the memory planner to pre-determine workspace, cache, and graph execution addresses, and simplifies the verification of state transitions for cancellation, failure, and recovery.

**Part 2: Prefill.** Inputs first undergo template rendering and tokenization, then enter the model in fixed-size blocks. Each block reads previously committed state and atomically advances the frontier. Timing must distinguish between host preparation, visual preprocessing, text prefill, and the first output token; file reading or model loading must not be conflated with throughput.

**Part 3: Decoding.** Standard decoding commits one token per round, whereas speculative decoding can verify multiple candidates and commit a contiguous prefix. Regardless of how many candidates are accepted, the public output, KV cache, loop state, and counters must all correspond to the same committed position, leaving no partially updated state.

**Part 4: Long Context.** As context grows, latency is jointly determined by fixed weight reads and the continuously growing attention cache reads. Reports should provide both absolute speed and relative retention rate, alongside the actual prompt token count, and document the cache format, maximum capacity, sampler, and graph execution status.

**Part 5: Reproducibility.** Stable inputs must be saved as the actual message files sent, with their source and token count recorded. Formal runs must not involve temporary web downloads, random question selection, or the exclusion of slower samples. Every reported number must be traceable back to a specific model, command, input, and service log.

**Part 6: Interpretation of Results.** A single isolated fastest run cannot prove stable performance, and a single high acceptance-rate text cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be presented separately, rather than mixed into a meaningless overall average.
