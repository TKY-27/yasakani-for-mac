# 发布流程

发布负责人必须准确保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但不要翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}

## 注意事项

操作员需检查前缀复用是否已禁用、缓存命中计数是否为零，以及是否有无关的 GPU 进程正在运行。自然停止的响应仍视为有效观测；因客户端断开连接而丢失的响应则不然。报告区分了服务器内部的 TTFT 与网络观测到的时间，并解释了第一个生成的 token 被分配给 prefill 阶段。

## 双语术语表 (Bilingual Glossary)

1. **Release owner** (发布负责人): 负责管理版本发布流程及合规性的主要责任人。
2. **Identifier** (标识符): 用于唯一标识特定实体或参数的唯一字符串或符号。
3. **Prose** (正文/散文): 指文档中除代码和结构化数据外的自然语言文本部分。
4. **Command-line flag** (命令行标志): 用于在终端命令中修改程序行为或启用特定功能的参数前缀（如 `-v` 或 `--verbose`）。
5. **Filename** (文件名): 用于标识存储设备上文件或目录名称的字符串。
6. **Phase** (阶段): 发布或执行流程中的一个特定步骤或时期。
7. **Evidence** (证据/凭证): 证明某个步骤已正确完成或状态符合预期的数据或记录。
8. **Fixture** (测试固件/测试数据): 在测试环境中预先准备好的静态数据或环境状态，用于确保测试的可重复性。
9. **Hash** (哈希/散列): 将任意长度的输入数据映射为固定长度输出的算法结果，常用于验证数据完整性。
10. **Prompt-token** (提示词 Token): 构成用户输入提示词的离散语言单元，通常由分词器生成。
11. **Generation** (生成): 模型根据输入上下文产生后续文本内容的过程。
12. **Warmup** (预热): 在正式测量或负载测试前，使系统达到稳定状态（如加载模型权重、建立连接池）的过程。
13. **Unmeasured** (未测量的): 指那些不计入最终性能统计或基准测试结果的请求或操作。
14. **Service** (服务): 在计算环境中提供特定功能或资源的软件组件或进程。
15. **Sequential** (顺序的): 指按特定顺序一个接一个地执行或排列，而非并行处理。
16. **Response** (响应): 服务器或模型对接收到的请求所返回的结果或数据。
17. **Invalidate** (使无效/作废): 标记数据、缓存或结果不再有效或不可用。
18. **Block** (块): 在数据处理或内存管理中，一组连续的数据单元或逻辑分组。
19. **Headline** (标题/头条): 报告中总结主要结论或关键指标的醒目部分。
20. **Prefix reuse** (前缀复用): 在推理过程中重新利用已计算过的相同前缀部分的 KV 缓存，以优化性能。
21. **Cache-hit** (缓存命中): 请求的数据或计算结果已在缓存中找到，无需重新计算或从慢速存储加载。
22. **GPU process** (GPU 进程): 占用图形处理单元（GPU）资源以执行计算任务的操作系统进程。
23. **Observation** (观测/观察值): 在实验或测试过程中记录到的具体数据点或现象。
24. **TTFT (Time To First Token)** (首 Token 延迟): 从发送请求到收到第一个生成 Token 之间的时间间隔。
25. **Prefill** (预填充): 推理阶段中处理输入提示词以生成初始 KV 缓存的步骤，通常发生在生成第一个 Token 之前。<|im_end|>
