# 发布流程

发布负责人必须原样保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译成中文，但不要翻译代码、JSON 键、命令行参数、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用功能已禁用，缓存命中次数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍被视为有效观察；因客户端断开连接而丢失的响应则不是。报告区分服务器内部的 TTFT 和网络观察到的时间，并解释首个生成的 token 归属于 prefill 阶段。

## 双语术语表

| English Term | 中文术语 | Note |
| :--- | :--- | :--- |
| release owner | 发布负责人 | 负责执行发布流程并保留关键标识符的人员。 |
| request_id | 请求 ID | 用于唯一标识单个推理请求的字符串。 |
| max_context | 最大上下文 | 模型处理的最大上下文长度限制。 |
| kv_dtype | KV 数据类型 | 键值（Key-Value）缓存存储的数据类型（如 fp16, int8）。 |
| mtp_rounds | MTP 轮数 | 多 token 预测（Multi-Token Prediction）的迭代轮数。 |
| fixture hash | 测试数据哈希 | 用于验证测试输入数据完整性的哈希值。 |
| prompt-token count | 提示词 Token 数 | 输入提示词中 Token 的总数。 |
| stop before generation | 生成前停止 | 在开始生成内容前终止流程的操作。 |
| warmup | 预热 | 正式测量前进行的非测量请求，以初始化系统状态。 |
| unmeasured request | 未测量请求 | 不纳入性能统计的测试请求。 |
| restart the service | 重启服务 | 故障发生时重新启动后端服务的操作。 |
| sequential responses | 顺序响应 | 按顺序连续生成的多个响应。 |
| invalidate the complete block | 使完整块失效 | 当测量失败时，丢弃整个测量数据块的操作。 |
| publish | 发布 | 将最终结果汇总并公之于众的阶段。 |
| summary | 摘要 | 包含整体性能指标的汇总数据。 |
| per-request rows | 每请求行 | 记录单个请求详细数据的表格行。 |
| withhold the headline | 保留头条数据 | 在验证完成前不公开主要性能指标的操作。 |
| prefix reuse | 前缀复用 | 利用相同前缀缓存以加速后续请求的机制。 |
| cache-hit count | 缓存命中次数 | 请求命中缓存的次数统计。 |
| GPU process | GPU 进程 | 占用图形处理器资源的操作系统进程。 |
| TTFT | 首 Token 时间 | Time To First Token，从请求发出到收到第一个 Token 的时间。 |
| prefill | 预填充 | 模型处理输入提示词并生成初始上下文的阶段。 |<|im_end|>
