# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。请将正文翻译为中文，但不要翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

## 备注

操作员需检查前缀复用（prefix reuse）已禁用，缓存命中计数（cache-hit count）为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍被视为有效观察；因客户端断开连接而丢失的响应则不是。报告区分了服务器内部 TTFT 和网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

### 双语术语表

1. **Release procedure / 发布流程**：指软件或模型版本从准备到最终发布的标准化步骤。
2. **Release owner / 发布负责人**：负责监督整个发布过程并确保合规的人员。
3. **Identifier / 标识符**：用于唯一识别请求或配置参数的字符串，如 `request_id`。
4. **Fixture hash / 测试夹具哈希**：用于验证测试数据完整性的哈希值。
5. **Prompt-token count / 提示词 Token 数**：输入提示词中包含的 Token 数量。
6. **Warmup / 预热**：在正式测量前运行非测量请求以稳定系统状态的过程。
7. **Unmeasured request / 未测量请求**：不计入性能统计的测试请求。
8. **Sequential responses / 顺序响应**：按顺序生成的多个响应，用于确保测量一致性。
9. **Invalidate / 使无效**：在测量失败时废弃当前数据块的操作。
10. **Withhold / 扣留**：在发布阶段暂停公开关键指标的操作。
11. **Prefix reuse / 前缀复用**：利用相同前缀缓存以加速推理的技术，此处需禁用。
12. **Cache-hit count / 缓存命中计数**：记录缓存成功命中次数的指标，此处需为零。
13. **GPU process / GPU 进程**：占用图形处理单元资源的后台进程。
14. **Valid observation / 有效观察**：符合实验条件、可用于分析的数据点。
15. **Client disconnected / 客户端断开**：导致响应丢失的网络中断情况。
16. **TTFT / 首字延迟**：Time To First Token，指从请求发出到收到第一个 Token 的时间。
17. **Network-observed time / 网络观测时间**：从客户端视角测量到的网络传输时间。
18. **Prefill / 预填充**：模型处理输入提示词并生成初始上下文的阶段。
19. **Max completion tokens / 最大完成 Token 数**：限制模型生成响应长度的参数。
20. **Seed / 随机种子**：用于确保随机过程可复现的固定数值。
21. **Stream / 流式传输**：是否以流式方式逐步返回生成内容的布尔值。
22. **KV dtype / KV 数据类型**：键值缓存（Key-Value Cache）所使用的数据类型。<|im_end|>
