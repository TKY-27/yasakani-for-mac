# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但不得翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

## 备注

操作员需检查前缀重用已禁用，缓存命中计数为零，且没有无关的 GPU 进程正在运行。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则无效。报告区分了服务器内部 TTFT 和网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

### 双语术语表 (Bilingual Glossary)

1. **Release procedure** / 发布流程：指软件版本从开发到正式发布的标准化步骤集合。
2. **Release owner** / 发布负责人：负责协调和执行特定版本发布任务的人员。
3. **Identifier** / 标识符：用于唯一识别数据对象或配置项的代码或字符串。
4. **Prose** / 正文：文档中除代码和结构化数据外的叙述性文字部分。
5. **Command-line flag** / 命令行标志：在终端命令中用于修改程序行为的参数选项（如 `-v`）。
6. **Filename** / 文件名：文件系统中用于标识文件的名称。
7. **Phase** / 阶段：工作流程中的一个特定时间段或步骤。
8. **Required evidence** / 所需证据：证明某阶段成功完成所必需的数据或日志记录。
9. **Failure action** / 失败操作：当某个步骤未满足条件时预设的应对措施。
10. **Fixture hash** / 测试夹具哈希值：用于验证测试数据完整性的哈希校验码。
11. **Prompt-token count** / 提示词 Token 数量：输入提示词经过分词器处理后产生的 Token 总数。
12. **Unmeasured request** / 未测量请求：用于预热但不计入性能统计的请求。
13. **Sequential responses** / 顺序响应：按时间顺序依次返回的一组模型输出结果。
14. **Invalidate** / 使无效：标记某组数据或测试结果不可用或不可信。
15. **Withhold** / 扣留/暂缓发布：暂时不公开或发布某些关键信息或功能。
16. **Prefix reuse** / 前缀重用：利用之前计算过的相同前缀部分的 KV 缓存以加速推理。
17. **Cache-hit count** / 缓存命中计数：成功从缓存中读取数据的次数。
18. **GPU process** / GPU 进程：占用图形处理器资源的操作系统进程。
19. **TTFT** / 首字延迟 (Time To First Token)：从发送请求到收到第一个生成 Token 的时间间隔。
20. **Prefill** / 预填充：模型处理输入提示词并构建初始上下文的状态阶段。
