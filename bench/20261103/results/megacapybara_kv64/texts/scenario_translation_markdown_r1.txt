# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但不得翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用已禁用，缓存命中计数为零，且没有无关的 GPU 进程正在运行。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则无效。报告区分服务器内部 TTFT 与网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

### 双语术语表

1. **Release procedure / 发布流程**：指软件版本从准备到发布的标准化操作步骤。
2. **Request ID / 请求标识符**：用于唯一标识单次 API 调用或用户请求的字符串。
3. **Max context / 最大上下文长度**：模型能够处理的最大输入 token 数量限制。
4. **KV dtype / KV 数据类型**：Key-Value 缓存存储时使用的数据精度类型（如 float16, int8）。
5. **MTP rounds / MTP 轮次**：Multi-Token Prediction 预测轮数，影响生成速度。
6. **Fixture hash / 测试夹具哈希**：用于验证测试数据完整性的哈希值。
7. **Prompt-token count / 提示词 Token 计数**：输入提示词中包含的 Token 总数。
8. **Unmeasured request / 未测量请求**：仅用于预热服务而不计入性能统计的请求。
9. **Sequential responses / 顺序响应**：按时间顺序连续返回的一组响应结果。
10. **Invalidate block / 使块失效**：当测试失败时，作废当前整个测试批次的数据。
11. **Withhold headline / 暂缓发布标题**：在数据不完整或异常时，暂时不公布主要结论。
12. **Prefix reuse / 前缀复用**：利用相同前缀的缓存来加速后续请求的处理。
13. **Cache-hit count / 缓存命中计数**：成功从缓存中读取数据的次数。
14. **GPU process / GPU 进程**：占用图形处理器资源的后台任务。
15. **Valid observation / 有效观测**：符合实验标准、可用于分析的有效数据点。
16. **Client disconnected / 客户端断开**：用户端主动或意外终止了与服务器的连接。
17. **Server-internal TTFT / 服务器内部首字延迟**：服务器内部记录的首个 Token 生成时间。
18. **Network-observed time / 网络观测时间**：客户端通过网络实际感知到的延迟时间。
19. **First generated token / 首个生成 Token**：模型输出的第一个字符或子词单元。
20. **Prefill / 预填充阶段**：模型处理输入提示词并构建初始上下文的阶段。
