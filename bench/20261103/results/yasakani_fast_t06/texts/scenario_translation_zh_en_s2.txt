**Part 1: Operational Boundaries.** The system services only one active request at a time, and all model state is exclusively owned by a single execution thread. This constraint is not a temporary defect, but a deliberate product choice for single-card local inference. It allows the memory planner to pre-determine workspace, cache, and graph execution addresses, and also makes state transitions for cancellation, failure, and recovery easier to verify.

**Part 2: Prefill.** Input first undergoes template rendering and tokenization, then enters the model in fixed-size blocks. Each block reads previously committed state and atomically advances the frontier. Timing must distinguish host preparation, visual preprocessing, text prefill, and the first output token; file reading or model loading must not be included in throughput calculations.

**Part 3: Decoding.** In standard decoding, one token is committed per round. In speculative decoding, multiple candidates can be verified and a contiguous prefix committed. Regardless of how many candidates are accepted, the public output, KV cache, loop state, and counters must all correspond to the same committed position; no partially updated state should remain.

**Part 4: Long Context.** As context grows, latency is jointly determined by fixed weight reads and the ever-growing attention cache reads. Reports should provide absolute speed, relative retention rate, and actual prompt token count, and record cache format, maximum capacity, sampler, and graph execution status.

**Part 5: Reproducibility.** Stable inputs must be saved as the actual message files sent, with source and token count recorded. Formal runs must not download web pages on the fly, randomly select questions, or delete slower samples. Every number must be traceable back to a specific model, command, input, and service log.

**Part 6: Result Interpretation.** A single isolated fastest run cannot prove stable performance, and a single high-acceptance text cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be presented separately, rather than mixed into a meaningless overall average.
