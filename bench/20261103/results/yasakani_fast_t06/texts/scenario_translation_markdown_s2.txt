# 发布流程

发布负责人必须严格保留 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但代码、JSON 键、命令行标志、文件名以及表格中的值不得翻译。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需确认前缀复用已禁用，缓存命中计数为零，且没有无关的 GPU 进程在运行。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则不是。报告区分了服务器内部 TTFT 与网络观测时间，并解释首个生成的 token 归属于 prefill 阶段。

## 双语术语表

| English Term | Chinese Term | Note |
|---|---|---|
| release owner | 发布负责人 | 负责发布流程整体协调与合规性的人员。 |
| request_id | 请求标识符 | 用于唯一标识单次 API 请求的字符串。 |
| max_context | 最大上下文长度 | 模型处理输入和输出 token 的上限。 |
| kv_dtype | KV 数据类型 | 键值缓存存储的数据精度类型（如 float16, bfloat16）。 |
| mtp_rounds | MTP 轮数 | 多 token 预测（Multi-Token Prediction）的迭代次数。 |
| fixture hash | 测试夹具哈希值 | 用于验证测试数据完整性的哈希校验值。 |
| prompt-token count | 提示词 token 数量 | 输入提示词中 token 的总数。 |
| warmup | 预热 | 在正式测量前运行非测量请求以稳定系统状态。 |
| unmeasured request | 非测量请求 | 不用于性能数据采集的预热请求。 |
| sequential responses | 连续响应 | 按顺序生成的多个模型响应。 |
| invalidate | 使无效 | 判定某次测试数据不可用。 |
| withhold | 扣留/保留 | 在条件未满足时暂不发布结果。 |
| headline | 标题/主要结论 | 报告中展示的核心性能指标或结论。 |
| model | 模型 | 具体的语言模型名称或版本。 |
| max_completion_tokens | 最大生成 token 数 | 模型单次响应中允许生成的最大 token 数量。 |
| seed | 随机种子 | 用于确保随机过程可复现的固定数值。 |
| stream | 流式传输 | 是否以流式方式逐步返回生成内容。 |
| prefix reuse | 前缀复用 | 复用相同前缀的 KV 缓存以加速推理。 |
| cache-hit count | 缓存命中计数 | 成功从缓存中检索到数据的次数。 |
| TTFT | 首 token 延迟 | Time To First Token，从请求发起到首个 token 生成的时间。 |
| prefill | 预填充 | 模型处理输入提示词并生成 KV 缓存的阶段。 |<|im_end|>
