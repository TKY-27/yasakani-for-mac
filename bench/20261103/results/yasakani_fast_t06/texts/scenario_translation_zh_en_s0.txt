**Part One: Operational Boundaries**  
The system services only one active request at a time, with all model state exclusively owned by a single execution thread. This constraint is not a temporary flaw but a deliberate product choice for single-GPU local inference. It allows the memory planner to pre-determine workspace, cache, and graph execution addresses, and makes state transitions for cancellation, failure, and recovery easier to verify.

**Part Two: Prefill**  
Input first undergoes template rendering and tokenization, then enters the model in fixed-size blocks. Each block reads previously committed state and atomically advances the frontier. Timing must distinguish host preparation, visual preprocessing, text prefill, and the first output token; file reading or model loading must not be included in throughput metrics.

**Part Three: Decoding**  
Standard decoding commits one token per iteration, while speculative decoding can verify multiple candidates and commit a contiguous prefix. Regardless of how many candidates are accepted, the public output, KV cache, loop state, and counters must all correspond to the same committed position; no partially updated state may remain.

**Part Four: Long Context**  
As context grows, latency is jointly determined by fixed weight reads and the continuously growing attention cache reads. Reports should provide absolute speed, relative retention rate, and actual prompt token count, and record cache format, maximum capacity, sampler, and graph execution state.

**Part Five: Reproducibility**  
Stable inputs must be saved as actual message files sent, with source and token count recorded. Formal runs must not involve on-the-fly web downloads, random question selection, or exclusion of slower samples. Every figure must be traceable to a specific model, command, input, and service log.

**Part Six: Result Interpretation**  
A single isolated fastest run cannot prove stable performance, and a single high-acceptance-rate text cannot represent all output scenarios. Code, narrative, translation, and structured content have different token distributions and should be presented separately, rather than mixed into a meaningless overall average.
