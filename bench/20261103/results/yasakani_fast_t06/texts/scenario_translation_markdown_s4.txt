# 发布流程

发布负责人必须准确保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但不得翻译代码、JSON 键、命令行标志、文件名或表格中的值。

| 阶段 | 所需证据 | 失败处理 |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需确认前缀复用已禁用，缓存命中计数为零，且没有无关的 GPU 进程正在运行。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则不是。报告区分了服务器内部 TTFT 和网络观测时间，并解释了第一个生成的 token 被分配给 prefill 阶段。

## 双语术语表

| 英文术语 | 中文术语 | 简要说明 |
|---|---|---|
| release owner | 发布负责人 | 负责管理发布流程与质量的人员 |
| request_id | 请求标识符 | 唯一标识一次 API 请求的 ID |
| max_context | 最大上下文长度 | 模型可处理的最大输入 token 数 |
| kv_dtype | 键值数据类型 | 用于存储 KV cache 的数据类型 |
| mtp_rounds | 多 token 预测轮数 | 多 token 预测迭代次数 |
| fixture hash | 测试数据哈希值 | 用于验证测试数据完整性的哈希 |
| prompt-token count | 提示词 token 数量 | 输入提示词中的 token 总数 |
| warmup | 预热 | 在正式测量前运行无测量请求以稳定系统 |
| unmeasured request | 无测量请求 | 不记录性能指标的请求 |
| sequential responses | 顺序响应 | 按顺序生成的多个响应 |
| invalidate the complete block | 使整个数据块失效 | 丢弃所有测量数据 |
| summary | 汇总 | 整体性能指标的摘要 |
| per-request rows | 单请求数据行 | 每个请求的详细性能数据 |
| withhold the headline | 保留头条结论 | 不发布主要性能结论 |
| prefix reuse | 前缀复用 | 复用相同前缀的 KV cache |
| cache-hit count | 缓存命中计数 | 命中缓存的次数 |
| GPU process | GPU 进程 | 占用 GPU 资源的进程 |
| TTFT | 首 token 延迟 | 从请求发出到第一个 token 生成的时间 |
| prefill | 预填充 | 处理输入提示词并生成 KV cache 的阶段 |
| stream | 流式传输 | 是否以流式方式返回响应 |
| seed | 随机种子 | 用于确保生成结果可复现的参数 |<|im_end|>
