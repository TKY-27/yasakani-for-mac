# 发布流程

发布负责人必须严格保留诸如 `request_id`、`max_context`、`kv_dtype` 和 `mtp_rounds` 等标识符。将正文翻译为中文，但代码、JSON 键、命令行标志、文件名或表格中的值不得翻译。

| Phase | Required evidence | Failure action |
|---|---|---|
| prepare | fixture hash and prompt-token count | stop before generation |
| warmup | one successful unmeasured request | restart the service |
| measure | five sequential responses | invalidate the complete block |
| publish | summary plus per-request rows | withhold the headline |

```json
{"model":"qwen3.6-35b-a3b","max_completion_tokens":1024,"seed":42,"stream":false}
```

## 备注

操作员需检查前缀复用已禁用，缓存命中计数为零，且没有无关的 GPU 进程处于活动状态。自然停止的响应仍被视为有效观测；因客户端断开连接而丢失的响应则无效。报告区分服务器内部 TTFT 与网络观测时间，并解释首个生成的 token 被分配给 prefill 阶段。

### 双语术语表 (Bilingual Glossary)

1. **Release procedure** / 发布流程：指软件版本从准备到发布的标准化操作步骤。
2. **Request ID** / 请求标识符：用于唯一标识单次 API 调用或系统请求的字符串。
3. **Max context** / 最大上下文长度：模型能够处理的最大输入 token 数量限制。
4. **KV dtype** / KV 数据类型：Key-Value 缓存存储时使用的数据精度类型（如 FP16, INT8）。
5. **MTP rounds** / MTP 轮次：Multi-Token Prediction（多 token 预测）算法中执行的迭代次数。
6. **Fixture hash** / 测试夹具哈希值：用于验证测试数据完整性和一致性的哈希校验码。
7. **Prompt-token count** / 提示词 Token 数：输入提示词中包含的 token 总数。
8. **Unmeasured request** / 未测量请求：用于预热但不计入性能统计的请求。
9. **Sequential responses** / 顺序响应：按时间顺序连续返回的一组响应结果。
10. **Invalidate block** / 使块失效：在测量过程中发现错误时，作废当前整个数据块的操作。
11. **Per-request rows** / 每请求行数据：报告中针对每个单独请求记录的详细数据行。
12. **Withhold headline** / 暂缓发布标题/结论：在数据不完整或有误时，暂时不公布最终结果。
13. **Prefix reuse** / 前缀复用：利用之前计算过的相同前缀部分以加速推理的技术。
14. **Cache-hit count** / 缓存命中计数：成功从缓存中读取数据的次数。
15. **GPU process** / GPU 进程：占用图形处理器资源的后台或前台程序。
16. **Valid observation** / 有效观测：符合实验标准、可用于分析的数据点。
17. **Client disconnected** / 客户端断开：用户端与服务端之间的网络连接中断。
18. **Server-internal TTFT** / 服务器内部首字延迟：服务器内部记录的首个 token 生成时间。
19. **Network-observed time** / 网络观测时间：客户端通过网络实际感知到的响应时间。
20. **Prefill** / 预填充：模型处理输入提示词并生成初始上下文的阶段。
